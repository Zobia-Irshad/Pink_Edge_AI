Clinical triage that runs
with the internet switched off.

Pink Edge AI is an offline-first triage assistant for rural Basic Health Units — mammography, tuberculosis chest X-ray, and maternal ultrasound — built to work on an edge box with no connectivity, no cloud dependency, and no patient identifiers leaving the device. Three interchangeable interfaces sit on one shared model backend.

What it is

A Lady Health Worker loads a scan, gets a preliminary triage verdict with a confidence figure and a localisation, and can forward it as a referral over 2G GSM when there is no data connection. A Senior Radiologist (PIN-gated) can override the assessment. Reports are cached locally in SQLite and sync later, if ever.

🔒 Offline by construction

The pixel-diff heuristic needs no model weights and no internet, ever. The trained classifiers run locally once downloaded. Being offline is verified by a suite that actually blocks every outbound socket — not by reading the code.

🛡️ No identifiers leave the device

Patient identifiers are stripped and replaced with a SHA-256 hex privacy hash before anything is displayed, cached, or transmitted. A dedicated suite checks that promise at every sink, including the GSM broadcast and the generated reports.

📏 Numbers you can audit

Every accuracy figure is measured on a group-disjoint held-out split and reported against a no-anatomy control floor, with per-class recall rather than one average. Where a number is weak, it says so.

Three interfaces, one backend

All three call the same run_triage() dispatcher, share the same model fallback order per modality, the same SQLite report cache, and the same privacy-hashing path. No inference logic is duplicated between them.

Measured results

Held-out accuracy for the locally-trained classifier in each modality. The control floor column is the score a linear classifier reaches on 8×8 crushed copies of the same images, where no anatomy is resolvable — that, not the chance line, is the bar a model actually has to clear.

⚠️ Maternal: the headline improved while the class that matters got worse. Fine-tuning took overall accuracy from 71.4% to 74.0%, but Bad Health recall fell from 53.0% to 46.3% — the model got better at separating Good from Med and pays for it by grading urgent scans as "follow-up". For triage a missed urgent case is the expensive error, so 74.0% is not a straightforward improvement: more than half of genuinely urgent scans are mislabelled either way. 106 of its 116 errors are Med↔Bad confusion; read instead as a plain healthy-vs-abnormal detector, the same model is 97.8% accurate.
Two caveats that travel with these numbers. The maternal severity boundary is a clinical convention this project applied by parsing pathology names out of filenames — not a radiologist's reading of these images; grading ventriculomegaly is a millimetre measurement a whole-image classifier has no mechanism to make. And tuberculosis' 83.0% control floor is high: its +6.9pp margin is modest, which makes it a useful screening aid rather than a confident reader of subtle disease.
Per-class recall, since an average hides the clinically critical class. Tuberculosis — active TB 93.3%, not-active 86.4%. Maternal — Good Health 100%, Med 75.8%, Bad 46.3%. Full confusion matrices are in the model report.

What auditing the data turned up

The datasets shipped with defects that inflate accuracy. Each was found by measurement, repaired by a reproducible seeded organiser script, and is now re-checked on every run by Tests/dataset_integrity_test.py — so none of them can quietly return.

  1. The tuberculosis split leaked almost completely. Its 9,917 images are augmentations of only 1,507 distinct base scans, and 699 of validation's 703 base scans also appear in training. The previously reported 82.5% was measured that way — it was scoring recoloured copies of its own training images. Re-split over base-scan groups, the honest figure is 89.9%.
  2. 82 chest X-rays carried both a positive and a negative annotation. The loader added such an image to both sets, so the same picture trained as active TB and as healthy at once. Now excluded and counted.
  3. 520 latent-TB images were being dropped silently. They are still excluded — latent infection is radiographically silent, so a chest X-ray supports neither answer — but the exclusion is now explicit in the config and recorded in the manifest.
  4. The maternal split leaked too. 1,384 images from only 106 base scans, with 104 of validation's 104 base scans also in training. Accuracy against it measured memorisation, so it was rebuilt over groups.
  5. Duplicate images hid under different filenames. Content-hashing the normalised images found one scan filed under two different pathologies, and two patient IDs holding the same image. Groups sharing an image are now merged before splitting, so a duplicate cannot straddle the split.
  6. The maternal classes come from two different source datasets, so a model could score well by recognising the source rather than the anatomy. That is precisely what the 8×8 control floor exists to measure — and why 57.7%, not 33.3%, is the number its accuracy is quoted against.

How it stays useful with no connection

Each modality tries several methods in an order set by measured accuracy, not by "online first". Green tiers need no network at all; amber tiers need a key and a connection, and are skipped without one.

🫁 Tuberculosis

Trained classifier→ Pixel-diff heuristic→ Hosted model→ Offline ViT

Reaches a real result with no key and no internet — the locally-trained classifier leads on measured accuracy.

🤰 Maternal Health

Hosted model→ 3-class severity model→ Pixel-diff heuristic→ Offline CNN

Three offline tiers behind the hosted one, so losing connectivity degrades the answer rather than removing it.

🎗️ Mammography

Hosted workflow→ Pixel-diff heuristic→ Trained classifier→ Local weights

The heuristic draws a real bounding box around whatever region actually differs from its reference images.

The pixel-diff heuristic needs no weights and no internet, ever. It averages your own local labelled datasets into "typical positive" and "typical negative" reference images, then compares a new scan against both. There is nothing to download and nothing to call.

How the claims are checked

Nine suites, 106 automated checks. They are written to catch this project's own overstatements — the offline claim is tested by removing the network, not by inspecting code, and a control check tries three escape routes first so a pass cannot be an artefact of accidental connectivity.

🔌 Offline validation 13 checks

Every outbound socket blocked and the model hub forced offline. Verifies all three modalities still produce results, that none claims a hosted source, and that cache, reports and both UIs still function.

🛡️ Privacy leak validation 10 checks

Checks the PII promise at every sink: the GSM/IoT broadcast, the SQLite cache, the generated text and PDF reports, and API-key hygiene.

🧪 Dataset integrity 18 checks

Per modality: no group leak across the split, no duplicates, balanced classes, a uniform pipeline, train/inference preprocessing parity re-derived byte-for-byte, and the model beating its own control floor by a required margin.

🔍 Fabrication audit

Submits the identical image three times per modality and diffs the results. A field derived from the image is identical every time; one that changes was generated, not measured — and is flagged if it sits inside a result claiming real inference.

✅ Full validation 19 checks

Imports, image synthesis, overlay drawing, a SQLite round-trip on a throwaway database, report generation, real-model inference on both synthetic and real samples, ground-truth cross-checks, and full feature sweeps of both UIs.

📋 Evidence report

Runs every suite, records their actual exit codes, and writes a dated document with the SHA-256 of each attested source file — so the report cannot silently outlive the code it describes.

The edge box it targets

Deployment code for an RK3588 single-board computer running in kiosk mode with NPU-accelerated inference, plus a UART bridge to an ESP32 + SIM800L companion that carries referrals out over 2G GSM when there is no data link.

Stated plainly: the hardware and Android paths have not been built or run against real hardware in this environment — no board, no Android SDK. Their READMEs say so too. Treat them as a starting point to verify on real hardware, not as a tested deployment.
